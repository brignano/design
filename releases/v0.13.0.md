Tailwind sites can now take the shared components without losing their layout: `controls.css` is `components.css` without the layout primitives whose names Tailwind already uses.

## Upgrading: what changes on your site

Nothing changes on upgrade. `components.css` is untouched. If your site uses Tailwind, switch to `controls.css` when you adopt the components.

## controls.css

- **`@brignano/design/controls.css`** is every component in `components.css` except `.container`, `.stack`, `.cluster`, `.grid`, `.section`, `.divider` and `.gap-2` … `.gap-6`. With `components.css` in a Tailwind site, every `grid` picked up auto-fit columns and every `gap-4` moved onto the `--s` scale.
- Import it after the tokens and the bridge, and declare the layer order first so the components sit under Tailwind's utilities:

```css
@layer theme, base, brignano.components, components, utilities;
@import "tailwindcss";
@import "@brignano/design/tokens.css";
@import "@brignano/design/tailwind.css";
@import "@brignano/design/controls.css";
```

- It is generated from `components.css` by `npm run controls`, and `npm run check` fails if the two drift.
- DESIGN.md §11 covers the setup, including `.prose` beside `@tailwindcss/typography`.
