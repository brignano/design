Cards now stand off the page in light mode, and the tokens get readable names, one JSON source and the first opt-in kits and product themes for design v1.0.

## Upgrading: what changes on your site

- **Cards look stronger in light mode.** `.card` gets a slightly darker edge (`--card-line`, neutral-200) and `--shadow-2`, so a grid of cards no longer reads as one sheet. Hovered `.card-link` lifts to `--shadow-3`. Dark mode is unchanged. Sites on a kit or a product theme keep their cards exactly as they were.
- **Tokens have new names; the old ones still work.** Reading an old name (`var(--n-200)`, `var(--i-ink)`) resolves to the new one until 1.0. *Setting* an old name no longer reaches the components, so if your site overrides `--i` or `--n-*`, set the new name instead.
- Nothing else changes on upgrade. Kits and themes are opt-in.

## New names

| Before | Now |
|---|---|
| `--n-0` … `--n-900` | `--neutral-0` … `--neutral-900` |
| `--i`, `--i-hover`, `--i-pressed` | `--action`, `--action-hover`, `--action-pressed` |
| `--i-ink`, `--i-ink-hover` | `--action-ink`, `--action-ink-hover` |
| `--i-surface`, `--i-line`, `--i-selection` | `--action-surface`, `--action-line`, `--action-selection` |
| `--on-i` | `--on-action` |
| `--i-disabled-bg`, `--i-disabled-ink` | `--disabled`, `--disabled-ink` |
| `--s1` … `--s9` | `--space-1` … `--space-9` |
| `--dur`, `--dur-fast`, `--dur-slow` | `--duration`, `--duration-fast`, `--duration-slow` |
| `--radius` | `--radius-card` |

`tokens/names.d.ts` exports `TokenName` and `DeprecatedTokenName` for type-checked token names. The Tailwind utilities (`text-interactive-ink`, `bg-card` and the rest) are unchanged.

## Tokens from JSON, in three tiers

- Every token is written once in `tokens/*.json` and `npm run build` generates `tokens.css`, `tokens.chart.css`, `tailwind.css` and the types. `npm run check` fails if they drift.
- Three tiers: primitives (the ramps), semantic (`--ink`, `--action`, `--line`) and component (`--button-radius`, `--card-line`, `--focus-ring`). `.card` is the first component to read its component tokens.

## Kits and product themes (opt-in until 1.0)

- **Kits:** Split, Ledger and Larch, each a whole look in `kits/<kit>.css`. Put `data-kit="<kit>"` on `<html>` or any element. Each is checked against every contrast floor the default look is held to, in both schemes.
- **Product themes:** a product's look in a few lines (`themes/<product>.theme`), generated to `themes/<product>.css` under `[data-product='<product>']` and refused if it misses a contrast floor. Ships for homelab, driftwood, guidebook, receipts and sites.
- ADR-0019 (one house look, a theme and a shell per product) and ADR-0020 (kits opt-in until 1.0). DESIGN.md §11 covers setup.
