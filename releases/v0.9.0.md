An identity that follows each product into its app, three templates for tool apps, one icon set, and a dark mode whose buttons are as strong as the light ones.

## Upgrading: what changes on your site

Most of this release is new and opt-in. These five things change on upgrade without you doing anything:

- **In dark mode the primary button is a deep blue with a white label** (it was a pale blue with dark text), and hover and pressed go darker. Everything else drawn in the same blue follows: checked boxes, switches, the selected segment, the current page number, count badges, progress bars, meters and spinners, the underline under the selected tab and the current nav link, info icons in messages and banners, the info pill, the product page's button, native range sliders, and the faint blue behind a hovered ghost button, a highlighted code line and selected text. Links and the focus ring look as before.
- **In dark mode the destructive button is a deep rust with a white label**, to match. Error messages, pills, field errors and toasts keep the paler rust.
- **Buttons, inputs, selects, the segmented control and menu items share an 8px corner.** Buttons were 12px and inputs 6px.
- **A brand glyph is amber until you set its product.** An inline SVG glyph in `.site-brand` used to draw in ink. Add `data-mark` to `<html>` (below) to give it your product's colour.
- **`.num` is mono, and now works anywhere.** It used to exist only inside `.table`. A table's figures are where most sites will notice; column labels are unchanged. If you already use a `num` class of your own outside a table, it now picks up the mono face and stops wrapping.

Two changes to check if you wrote custom controls:

- A destructive button fills with `--danger-fill` (and `--danger-fill-hover`, `--danger-fill-pressed`) and labels with `--on-danger`, not `--danger` and `--on-i`. `--on-i` is now white in both themes.
- Text coloured with `--i-hover` (a hovered link of your own) should move to the new `--i-ink-hover`. In dark `--i-hover` is now a deep fill, too dark to read as text. The shared `.link` and `.prose` links already use it.
- Under `prefers-reduced-motion`, `tokens.css` now turns off view transitions on the page, your own included.

## Identity

Three things now make a screen recognisably one of these products (ADR-0014).

**A product's mark follows it everywhere.** Set it once:

```html
<html data-mark="teal">   <!-- or "violet", "magenta" -->
```

The brand glyph in the site header, the app shell and on error pages draws in that colour, as it already did on the product page. The name beside it stays ink, and buttons and links stay cobalt on every product. `data-mark` also works on `<html>` for product pages now, not only on `.pp`. New token: `--mark-current`.

**A mono voice.** New classes in `components.css`:

- `.eyebrow`: a small uppercase mono label above a screen's heading that says where you are. One per screen. Write it in sentence case; the CSS uppercases it.
- `.num`: mono with tabular figures, for any number, date, time or code. It doesn't wrap, so a date never breaks in two.

**One heavy moment.**

- `.display`: an error code or a single headline figure in Geist at weight 800. At most once a screen.
- `.stamp`: the `A|B` monogram at the same weight. Mark it up as `<span class="stamp" role="img" aria-label="Anthony Brignano">A|B</span>`.
- `.rule`: the short bar above a hero heading, in the product's mark.

The trail is no longer part of the identity.

## Templates for tool apps

Import one after `components.css`:

- `templates/app-shell.css`: the frame a tool app sits in. A header, a sidebar that collapses to an icon rail, the main view and an optional detail panel. It follows its own width, so the same markup is a phone layout (the sidebar and details become sheets), a tablet layout and a three-column desktop.
- `templates/settings.css`: one section per topic, description on the left and controls on the right, each section with its own Save, and a danger zone.
- `templates/error.css`: 404, 500 and offline pages. The product mark, the code, one line of what happened and one way forward.

## Icons

`icons/` is now in the package: 46 outline icons from Lucide on a 24px grid, in `currentColor`. Paste one inline and it takes its text's colour; size it with `.icon-sm`, `.icon` or `.icon-lg`. Each one is at `@brignano/design/icons/<name>.svg`. The [icons page](https://design.brignano.io/previews/icons.html) is searchable and copies the SVG.

## Motion

Two small things a control may now do, both only when the person acts and both off under reduced motion (ADR-0015):

- A `.btn` settles by 2% while it is pressed.
- A switch of view may cross-fade. Wrap the swap in `document.startViewTransition()`; the tabs page shows how. The package styles nothing on the transition, so it won't change one you already use.

## New tokens

- **Type:** `--weight-regular`, `--weight-medium`, `--weight-semibold`, `--weight-heavy`; `--leading-display`, `--leading-title`, `--leading-ui`, `--leading-body`; `--tracking-title`, `--tracking-display`, `--tracking-caps`. In `tailwind.css` they add utilities such as `leading-display` and `tracking-title`; Tailwind's own `leading-tight` and `tracking-tight` are untouched.
- **Shape:** `--radius-control` (8px), also in `tailwind.css` as `rounded-control`.
- **Stacking:** `--z-raised`, `--z-sticky`, `--z-float`, `--z-skip`, `--z-toast`.
- **Colour:** `--i-ink-hover`, `--mark-current`, `--danger-fill`, `--danger-fill-hover`, `--danger-fill-pressed`, `--on-danger`. `--i-ink-hover` (as `interactive-ink-hover`), the danger fills and `--on-danger` are also in `tailwind.css`.

## Smaller things

- **Print.** Any page now prints in the light theme whatever the screen showed, without sticky headers, shadows, popovers or screen-only buttons. Cards and table rows stay whole across a page break, and `.prose` writes an outside link's address after it.
- **Headings balance their line breaks**, and running text avoids a one-word last line.
- **The tool tier's smallest text is 12px on touch screens** (it was 11px).
- **A stat tile's delta** no longer strands a word on its own line.
- **A table's unsorted sort arrow** asks for its text form, so a phone shouldn't draw it as an emoji.
- **Content guidelines.** DESIGN.md §15 covers the words inside a product (buttons, errors, empty states, dates, numbers), each rule with a do and a don't, on the [writing page](https://design.brignano.io/previews/writing.html).
- **Every component page is its docs page**: a snippet to copy, when to use it, when not to, and accessibility notes.
