A shared component layer: the controls and patterns every brignano site was rebuilding by hand now ship in the package as plain CSS, plus page templates for articles, docs, changelogs, legal pages and transactional email.

## Components

```css
@import '@brignano/design/tokens.css';
@import '@brignano/design/components.css';
```

`components.css` is plain CSS classes, no framework and no script. Everything sits in the `brignano.components` cascade layer, so your own CSS and Tailwind utilities win without `!important`. Native elements come first (`<dialog>`, `popover`, `<details>`, `<progress>`), and state comes from real attributes (`disabled`, `aria-invalid`, `aria-current`, `aria-busy`), never from state classes. Every control reaches 44px on touch screens and holds up in forced-colours mode and under reduced motion.

- **Controls:** buttons and inline links (`.btn`, primary, secondary, ghost, danger, three sizes, icon, busy); text fields with hint, error and affix (`.field`); checkboxes and radios drawn from the tokens, switch and segmented control.
- **Feedback:** messages and banners (`.msg`, `.banner`); status pills, count badges and removable tags; toasts with separate polite and urgent lists; spinner, skeleton, progress, meter and empty state.
- **Overlays:** dialog and sheet on `<dialog>`; popover and action menu anchored to their opener; tooltips on `interestfor`, with a hover and focus fallback. Overlays may move briefly as they open and close (ADR-0013).
- **Layout and navigation:** container, stack, cluster, grid, section and divider; site header with a no-script phone menu, nav and footer; tabs, breadcrumb, pagination and load more; disclosure and accordion.
- **Content and data:** card; table with a sticky header and sortable columns; key-value list and stat tile; avatar, keycap, inline code and code blocks; blockquote and figure; `.prose` for long-form text.

New tokens for code: `--code-surface`, `--code-ink`, `--code-keyword`, `--code-string`, `--code-comment` and `--code-highlight`, also in `tailwind.css`. Syntax colour stays inside the existing palette, so code adds no new hue.

Every component has a live page, in both themes, on [design.brignano.io](https://design.brignano.io).

## Page templates

Import one after `components.css`:

- `templates/article.css`: one layout for blog posts and product docs, with a table of contents and a pager.
- `templates/changelog.css`: releases newest first, each linkable.
- `templates/legal.css`: privacy policy and terms, with a table of contents.
- `templates/email.html` and `email.txt`: a transactional email in light mode, table-based with inline styles. Fill its colours with `node node_modules/@brignano/design/scripts/email-tokens.mjs > email.html` (or import `fill()` from `@brignano/design/scripts/email-tokens.mjs`), which resolves the colours from `tokens.css`, so no hex is copied by hand.

`product-page.css` is unchanged and still stands on its own: product pages need nothing new.
