Use it

<div class="tabs">
  <div class="tabs-list" role="tablist" aria-label="Trip">
    <button type="button" role="tab" id="t1" aria-selected="true" aria-controls="p1">Itinerary</button>
    <button type="button" role="tab" id="t2" aria-selected="false" aria-controls="p2" tabindex="-1">Bookings</button>
  </div>
  <div class="tabs-panel" role="tabpanel" id="p1" aria-labelledby="t1" tabindex="0">…</div>
  <div class="tabs-panel" role="tabpanel" id="p2" aria-labelledby="t2" tabindex="0" hidden>…</div>
</div>

Use when

  • One thing has a few views people switch between, like a trip's itinerary, bookings and notes.
  • Two to six short labels.

Don't use when

  • The tabs go to different pages. Use the site nav with aria-current="page".
  • People need to compare the views side by side. Show them together.
  • Choosing a value in a form. Use a segmented control.

Behaviour your script owns

Design ships the look; your app writes the script. This page uses the reference version below the fold.

  • Click or Enter/Space selects a tab: set aria-selected="true" on it and "false" on the rest, and show only its panel (hidden on the others).
  • Left and Right arrows move to the previous and next tab and select it; Home and End go to the first and last. Skip aria-disabled tabs.
  • Optional: wrap the swap in document.startViewTransition() and the panels cross-fade over the system's fast duration. Skip it under prefers-reduced-motion; a browser without the API swaps at once. Never run it on load.
  • Only the selected tab is in the tab order (tabindex="0"); the others are tabindex="-1". Tab from the list moves into the panel.

Accessibility

  • Give the tablist an aria-label naming what the tabs switch.
  • Each tab's aria-controls names its panel; each panel's aria-labelledby names its tab.
  • The selected tab is shown by the underline and by stronger ink, not by colour alone.
