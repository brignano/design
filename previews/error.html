Use it

@import '@brignano/design/tokens.css';
@import '@brignano/design/components.css';
@import '@brignano/design/templates/error.css';

<main class="error-page">
  <div class="error-page-block">
    <a class="error-page-mark" href="/"><svg aria-hidden="true" …></svg>Breakeven</a>
    <p class="error-page-code">404</p>
    <h1 class="error-page-title">This page doesn't exist</h1>
    <p class="error-page-body">It may have moved, or the link has a typo.</p>
    <a class="btn btn-primary" href="/">Go to the home page</a>
  </div>
</main>

Use when

  • A page isn't there (404), the server failed (500), or a page or app shell has no network (offline).
  • The whole page failed. Give it the error page, not a message inside an empty layout.
  • For the words, follow Errors in the content guidelines.

Don't use when

  • One part of a page failed. Use a message (.msg-danger) in that part and keep the rest working.
  • A list is empty. That's an empty state, not an error.
  • You'd add a joke, an illustration or a second button. One way forward is the point.

The three pages

  • 404: say the page doesn't exist and link home. Keep the URL as it is so the person can fix a typo.
  • 500: say it's on your side, not theirs, and offer to try again. Don't show a stack trace. If support will ask for a request ID, put it in .error-page-ref, which sits after the words.
  • Offline: say they're offline and offer to try again. Only a service worker can show it: precache the page, its CSS and the mark (they're stored as 200s), and return the page from the fetch handler when the network fails.
  • Serve 404 and 500 with their real status codes, so crawlers and monitors see the failure. For planned maintenance or overload, use the 500 page's shape with a 503 and Retry-After.
  • "Try again" is a link to the same page (href=""), so it reloads with no script.
  • The code above the title is the page's label. It's the one exception to codes going after the words (Errors); a request ID still goes after.

Accessibility

  • The <title> says what happened first ("Page not found · Breakeven"), because a screen reader announces it before anything else.
  • The title is the page's one <h1>, and the page sits in <main>.
  • The mark is a link home with the product name as text; its svg is aria-hidden.
  • The mark and the button are the only tab stops, in that order, and both show the focus ring.
  • The code is plain text in a muted colour that still meets 4.5:1. The title carries the meaning, so the code is never the only sign.
