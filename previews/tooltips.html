Use it

<span class="tooltip-wrap">
  <button class="btn btn-ghost btn-icon" interestfor="tip-share" aria-labelledby="tip-share">…</button>
  <span class="tooltip" id="tip-share" popover="hint" role="tooltip">Share trip</span>
</span>

Use when

  • An icon button needs a visible name on hover and focus, like the trip tools above.
  • Names only. One short phrase that names what the button does.
  • You can live with a beta: only Chromium ships interestfor, so other browsers get the CSS fallback described below.

Don't use when

  • It says a sentence, holds a link, or says something the reader must know. Use a popover, or put it on the page.
  • It would be the only place something is said. Touch users don't hover.
  • The button already has a visible text label. A tooltip only repeats it.

Where it opens

With interestfor support, the browser opens it as a hint popover above the trigger (below if there's no room) and Esc dismisses it. Only Chromium ships interestfor today, which is why this component is in beta. Elsewhere, .tooltip-wrap shows it on hover and focus. No script either way. That fallback can't close on Esc or flip at the top of the viewport, and a parent with overflow: hidden clips it.

Timing

300ms in, nothing out. It stays open while the pointer is on it, so someone using a magnifier can move onto it to read it. With reduced motion there's no fade, but the delay stays.

Accessibility

  • The name comes from the tooltip. aria-labelledby on the trigger points at the tooltip, so screen readers hear the same words people see, with or without hover.
  • Give the tooltip role="tooltip" and popover="hint". It opens on keyboard focus as well as hover.
  • Esc dismisses it only in browsers with interestfor (Chromium today). In the CSS fallback it closes when focus or the pointer leaves.
  • It stays open while the pointer is on it, so it can be read with a magnifier. In forced colours it keeps a visible border.
