Audit command

A check an app runs in CI. It fails when the app styles around the system: a colour, font, radius, shadow or spacing value that isn't a token, or a token name the package doesn't define.

Run it

No install and no config. Give it files or folders; with none it scans the current folder. It reads CSS, HTML, JSX/TSX, Astro and Svelte, skips node_modules, anything in .gitignore and anything listed in a design-audit.ignore file (one path or glob per line), and exits 1 on any error.

npx @brignano/design audit src
npx @brignano/design audit --json
npx @brignano/design audit --spacing=error

Each finding names its file, line and column:

src/card.css:12:3  error    colour         colour literal rgb() (use a colour token)
src/card.css:14:3  error    border-radius  border-radius 6px is not a token (use var(--radius-sm), …)
src/card.css:15:3  warning  spacing        padding 12px is not a token (use var(--space-1) to var(--space-9))

3 files scanned: 2 errors, 1 warning, 1 open exception.

What it fails on

  • A colour literal: a hex, rgb(), hsl(), oklch() and the other colour functions. A function that reads a token, like rgb(var(--ink) / 50%), is fine.
  • A Tailwind arbitrary colour: bg-[…], text-[…] and the rest, when the brackets hold a literal colour.
  • A font-family or box-shadow that isn't var(--…).
  • A border-radius with a length that isn't a token. 0 and percentages pass.
  • A padding, margin or gap with a length that isn't a token. A warning for now; --spacing=error makes it an error. 0, auto and percentages pass.
  • A var(--name) the package doesn't define. Names come from the package's own tokens.css, tokens.chart.css, kits and themes, so a renamed or invented token is caught. Tailwind's --tw-* are left alone.

An SVG file or an image is never a finding. Inline SVG in markup is. Comments are skipped.

When the system lacks something

File an issue in brignano/design, then wait or take an exception. Never style around the gap in the app: the fix belongs here, so every app gets it.

One escape hatch, on the line or the line above it, in any comment style:

/* design-exception: brignano/design#123 */
.hero { border-radius: 14px; }

It passes while that issue is open and fails the day the issue closes. The audit counts open exceptions in its summary and in --json, so they stay visible. If GitHub can't be reached the exception passes with a warning, so CI never breaks on a network error.

In CI

Add one step to the app's workflow. --json gives findings, exceptions, warnings and a summary with errors, warnings and openExceptions.

- run: npx @brignano/design audit src

The audit reads names from the version of the package it runs from, so pin @brignano/design in the app like any dependency.
