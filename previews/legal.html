Use it

@import '@brignano/design/components.css';
@import '@brignano/design/templates/legal.css';

<main class="legal">
  <header class="legal-header">
    <h1>Privacy policy</h1>
    <p class="legal-updated">Last updated <time datetime="2026-11-07">7 Nov 2026</time></p>
  </header>
  <div class="legal-body">
    <nav class="legal-toc" aria-labelledby="toc-title">
      <h2 class="legal-toc-title" id="toc-title">On this page</h2>
      <ol><li><a href="#collect">What we collect</a></li>…</ol>
    </nav>
    <div class="prose"><h2 id="collect">What we collect</h2>…</div>
  </div>
</main>

Use when

  • Privacy policy, terms of service, acceptable use: any page that is mostly text and gets linked to from a footer.
  • Every site with a lead form needs a privacy page (fleet lead standard).
  • Leave the contents list out when the page has fewer than four sections.

Don't use when

  • Articles and docs pages, which get their own template.
  • Release notes: use the changelog template.
  • Cookie banners aren't part of this; no site uses cookies that need one.

Rules

  • Change "Last updated" whenever the wording changes, and only then.
  • Plain words, short sections, one h2 per topic. The contents list mirrors the h2s.
  • Mark the section in view with aria-current="location" if your app tracks it; the template doesn't need it.

Layout

  • Under 52rem (a phone, or a half-width panel like the ones above), the contents list is a card above the text.
  • From 52rem, it's a sticky column on the left.
  • That's a container query on .legal, so it follows the column, not the screen.

Accessibility

  • The contents list is a <nav> labelled by its heading, so it shows up in landmark lists.
  • Headings get scroll-margin-top, so a jump doesn't land them against the top edge.
  • Contents links reach 44px on touch.
