Dialog and sheet

Native <dialog> with showModal(): the page behind goes inert, Esc closes it and focus goes back to the button that opened it. A sheet comes in from the right on a wide screen and from the bottom on a phone. Opening and closing take 150ms, and are instant with reduced motion (ADR-0013).

Use it

<button class="btn" commandfor="rename" command="show-modal">Rename</button>

<dialog class="dialog" id="rename" aria-labelledby="rename-title">
  <div class="dialog-header">
    <h2 class="dialog-title" id="rename-title">Rename trip</h2>
    <form method="dialog">
      <button class="btn btn-ghost btn-icon btn-sm dialog-close" aria-label="Close">…</button>
    </form>
  </div>
  <div class="dialog-body">…</div>
  <div class="dialog-footer">
    <form method="dialog"><button class="btn">Cancel</button></form>
    <form method="dialog"><button class="btn btn-primary" value="save">Save name</button></form>
  </div>
</dialog>

Use when

  • A short task needs the person's full attention before they go on, like renaming a trip.
  • A destructive action needs a confirm, like deleting a trip. Use .dialog-confirm.
  • A set of filters or options is too long for the page. Use .sheet.
  • For the words, follow Confirmations in the content guidelines.

Don't use when

  • The content is short and needs no Save button. Use a popover.
  • You only need to say something happened. Use a toast.
  • The task is long or has many steps. Give it its own page.
  • A dialog is already open. Close the first, or put the second step inside it.

Behaviour

  • Open with dialog.showModal(). Where the browser supports commandfor and command="show-modal", a button opens it with no script; this page adds a three-line fallback for browsers that don't.
  • Close with a button inside <form method="dialog"> or with Esc. The close button in the header is always there.
  • A confirm names the action on its destructive button (“Delete trip”), never “OK”, and puts autofocus on the safe choice.
  • Never open a dialog on top of a dialog. Close the first, or put the second step inside it.
  • Scroll locking is what showModal() gives: the page behind can't be interacted with. Locking the page's scroll as well is up to you.

Accessibility

  • Use the native <dialog> with showModal(): the page behind goes inert, Esc closes it, and focus goes back to the button that opened it.
  • Point aria-labelledby at the .dialog-title, so screen readers announce the title when it opens.
  • The icon-only close button needs aria-label="Close".
  • Use <div>s for the header and footer. A <header> or <footer> inside a dialog reads as the page's banner or footer landmark.
  • Opening and closing are instant with reduced motion. In forced colours the dialog keeps a visible border.
