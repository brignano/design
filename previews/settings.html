Use it

@import '@brignano/design/tokens.css';
@import '@brignano/design/components.css';
@import '@brignano/design/templates/settings.css';

<main class="settings">
  <h1 class="settings-title">Settings</h1>
  <form class="settings-section" aria-labelledby="profile-h">
    <div class="settings-intro">
      <h2 id="profile-h">Profile</h2>
      <p>How other people see you on shared trips.</p>
    </div>
    <div class="settings-fields"><div class="field">…</div></div>
    <div class="settings-save">
      <p class="settings-save-note" role="status"></p>
      <div class="settings-save-actions" hidden>
        <button type="reset" class="btn">Discard</button>
        <button class="btn btn-primary">Save profile</button>
      </div>
    </div>
  </form>
</main>

// your script, per section form
const note = form.querySelector('.settings-save-note');
const actions = form.querySelector('.settings-save-actions');
const heading = form.querySelector('h2'); // has tabindex="-1"
const done = (text) => { heading.focus(); actions.hidden = true; note.textContent = text; };
form.addEventListener('input', () => { note.textContent = 'Unsaved changes'; actions.hidden = false; });
form.addEventListener('reset', () => done(''));
form.addEventListener('submit', async (e) => {
  e.preventDefault();
  await save(new FormData(form));          // on error: mark the fields, keep the bar
  for (const el of form.elements) {         // so Discard can't undo the save
    if ('defaultValue' in el) el.defaultValue = el.value;
    if ('defaultChecked' in el) el.defaultChecked = el.checked;
  }
  done('Profile saved');
});

Use when

  • A tool app needs a settings screen: profile, preferences, notifications, workspace.
  • Fields that are sent together go in one <form> section with its own save bar.
  • A setting that takes effect the moment it flips is a switch, in a section with no save bar.
  • For the words, follow Buttons and links and Confirmations in the content guidelines.

Don't use when

  • Sign-in, sign-up or account recovery. Cloudflare Access owns sign-in.
  • One Save for the whole page. Save each section, so a change in one isn't lost to an error in another.
  • A single preference. A switch in a menu is enough.

The save bar

  • Its buttons carry hidden until the section changes. Its note is always rendered and starts empty; your script writes "Unsaved changes" into it on the form's first input event.
  • Discard is a type="reset" button, which puts back each field's default value. So after a save, copy every value into its default (defaultValue, defaultChecked, defaultSelected), or Discard would quietly undo the save.
  • After a save, the note says so ("Profile saved") and the buttons hide. After an error, mark the fields as the text field page shows and keep the buttons up.
  • It sits right under the section's fields, so keep sections short enough that the bar is in view while you edit them. Split a long one in two.
  • The save button names the section ("Save profile").
  • .settings is a size container, so give its wrapper a definite width. Inside a box that sizes to its content, it collapses.

Accessibility

  • Each section is a <form> or <section> labelled by its heading (aria-labelledby), so a screen reader can jump between them.
  • The note is a role="status" that is always rendered and starts empty, so "Unsaved changes" and "Profile saved" are announced as they're written, without moving focus.
  • Save and Discard hide themselves, so move focus to the section's heading (tabindex="-1") before hiding them. Otherwise focus drops to the page.
  • Switches keep role="switch" and their label. The change itself is the feedback.
  • A danger action opens a .dialog-confirm whose safe button has autofocus. Esc closes it and focus goes back to the button.
