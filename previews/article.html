Article and docs page

One template for blog posts and product docs: title, date, reading time, the text and previous/next links. Docs mode adds a section nav and an "On this page" list.

Light

Set up a new site

7 Nov 20263 min read

Every site starts from the same two files. This page shows how an article or a docs page reads with them; the words are placeholder.

Install

Add the package, then import the tokens before anything else.

npm install @brignano/design

Import the layers

Components sit in one cascade layer, so your own CSS wins without !important.

  • tokens.css first.
  • components.css next.
  • Templates last, only on the pages that use them.

With Tailwind

Import tailwind.css after Tailwind itself, and the tokens become utilities.

Pick a tier

Tools stay quiet; marketing pages get more room. Add .tier-marketing to the page root for the second.

Use it

@import '@brignano/design/components.css';
@import '@brignano/design/templates/article.css';

<!-- Article -->
<main class="article">
  <header class="article-header">
    <h1>Title</h1>
    <p class="article-meta"><time datetime="2026-11-07">7 Nov 2026</time><span>3 min read</span></p>
  </header>
  <div class="prose">…</div>
  <nav class="article-pager" aria-label="More articles">
    <a rel="prev" href="…"><span class="article-pager-label">Previous</span>Title</a>
    <a rel="next" href="…"><span class="article-pager-label">Next</span>Title</a>
  </nav>
</main>

<!-- Docs: wrap it -->
<div class="article-docs"><div class="article-docs-layout">
  <details class="disclosure article-nav"><summary>Docs</summary>
    <nav aria-label="Docs">
      <p class="article-nav-heading">Guides</p>
      <ul><li><a href="…" aria-current="page">…</a></li></ul>
    </nav>
  </details>
  <details class="disclosure article-toc"><summary>On this page</summary>
    <nav aria-label="On this page"><ol><li><a href="#…">…</a></li></ol></nav>
  </details>
  <main class="article">…</main>
</div></div>

Use when

  • Blog posts and write-ups: the plain article.
  • Product docs with more than a couple of pages: docs mode.

Don't use when

  • Release notes: the changelog template.
  • Privacy and terms: the legal template.
  • A blog index or search: not part of this template.

Rules

  • Reading time is words ÷ 200, rounded up. Leave it out under a minute.
  • Previous and next come from rel; leave either out at the ends.
  • Mark the current page in the section nav with aria-current="page". If your app tracks the section in view, mark it in "On this page" with aria-current="location".
  • Label each <nav> with the words its summary shows; the wide layout uses that label as the list's title.

Layout

  • Under 48rem, both navs are disclosures above the text.
  • From 48rem, the section nav is a sticky left column; from 60rem, "On this page" is a sticky right column.
  • Those are container queries on .article-docs, so they follow the column, not the screen.
  • Shown as columns, the disclosures stay open through ::details-content. Browsers without it (Firefox before 143, Safari before 18.4) keep the disclosure, which still works.

Accessibility

  • Each list is a labelled <nav> and the disclosures are native <details>, so no script is needed.
  • In the wide layout the summaries are hidden, so there's no toggle that does nothing.
  • Nav links, summaries and the pager reach 44px on touch. The separator in the meta line is silent to screen readers.
