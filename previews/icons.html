    Use it

    <!-- paste the file's <svg>, then add the class and aria-hidden -->
<svg class="icon" aria-hidden="true" viewBox="0 0 24 24" …>…</svg>

<!-- an icon alone in a button: the button carries the name -->
<button class="btn btn-ghost btn-icon" aria-label="Close"><svg class="icon" aria-hidden="true" …>…</svg></button>

    Use when

    • A state needs its icon beside its word: info, circle-check, triangle-alert, circle-x.
    • A control is known by its shape: close, menu, search, copy, the chevrons.
    • An icon button needs a glyph; give the button an aria-label.

    Don't use when

    • It's a brand logo. Keep Simple Icons or the brand's own file for those.
    • The icon would be the only sign of a state. Add the word.
    • It would decorate a heading or a paragraph. The words are enough.
    • You need one that isn't here. Add it to the set from Lucide in a PR rather than drawing or importing another set.

    Sizes and colour

    • .icon-sm, .icon and .icon-lg are 1.25 times --text-sm, the body size and --text-lg, so they track the tier. Inside .btn an svg sizes itself the same way.
    • Every icon strokes in currentColor: set the colour on the text, never on the icon. That only works inline: an svg loaded through <img> or a CSS url() draws black, so paste the markup.
    • The files keep Lucide's names. The licence is in icons/LICENSE and ships with the package.

    Accessibility

    • A decorative icon next to its word takes aria-hidden="true", so it isn't read twice.
    • An icon-only button or link needs an aria-label that says what it does, not what it shows: "Close", not "X".
    • Icons inherit the text colour, so they meet the same contrast as the words beside them, and forced colours repaint them with the text.
