Select menu

The way to pick one option from a list. A button shows the choice and opens a menu of radio items, so the list looks the same on every device. Never a native <select>.

Use it

<div class="field">
  <label id="plan-l" for="plan">Plan</label>
  <button type="button" class="select-menu" id="plan" popovertarget="plan-list"
          aria-haspopup="menu" aria-expanded="false" aria-labelledby="plan-l plan-v">
    <span class="select-menu-value" id="plan-v">Standard</span>
  </button>
  <div class="popover" id="plan-list" popover>
    <div class="menu" role="menu" aria-labelledby="plan-l">
      <button type="button" class="menu-item" role="menuitemradio" aria-checked="true" data-value="standard">
        <span class="menu-item-text">Standard<small>Up to five sites</small></span>
      </button>
      <button type="button" class="menu-item" role="menuitemradio" aria-checked="false" data-value="custom">
        <span class="menu-item-text">Custom</span>
      </button>
    </div>
  </div>
  <input type="hidden" name="plan" value="standard">
</div>

Use when

  • Someone picks one of many options in a form: a plan, a region, a country.
  • A toolbar sorts or filters a list by one choice. Add .select-menu-inline so the button fits its words.
  • An option needs a line of explanation. Put it in <small> under the label.

Don't use when

  • Never a native <select> in product UI: its open list is the operating system's, and differs on every device.
  • There are two to four options: use radios or a segmented control, so they are all visible.
  • People pick several: use checkboxes.
  • The list is a set of actions, not a value: use a popover menu.

Parts

  • .select-menu is the button. It looks like a text field, with a chevron, and takes the same states: aria-invalid="true" turns the edge to --danger, disabled goes neutral, data-empty shows its prompt in the placeholder colour.
  • The list is a .popover holding a .menu, so anchoring, light dismiss and flipping when there is no room come from the popover. It is at least as wide as the button.
  • Each item is a .menu-item with role="menuitemradio". The checked one has aria-checked="true", a check mark and a medium weight. A <small> inside .menu-item-text adds a one-line hint.
  • A hidden input keeps the value for a form. A disabled item says why in its hint.

The script

The CSS is the design system's; the behaviour is the product's, as with tabs. Copy this, or write the same contract: it keeps the choice, the value and the keys. Without script, a .field can hold a native <select>, which stays styled as the fallback until the script swaps it.

// The select menu's script contract (issue 198). Copy it into the product: the
// design system ships the CSS, the product owns the behaviour, as with tabs.
// Finds every .select-menu button and the .menu its popovertarget opens.
(() => {
  const SEL = '[role="menuitemradio"]:not(:disabled)';
  for (const btn of document.querySelectorAll('.select-menu')) {
    const pop = document.getElementById(btn.getAttribute('popovertarget'));
    if (!pop) continue; // a disabled menu has no list
    const items = () => [...pop.querySelectorAll(SEL)];
    const value = btn.querySelector('.select-menu-value');
    const hidden = btn.closest('.field')?.querySelector('input[type="hidden"]');
    let typed = '', clear;

    pop.addEventListener('toggle', (e) => {
      btn.setAttribute('aria-expanded', e.newState === 'open');
      if (e.newState === 'open') (pop.querySelector('[aria-checked="true"]') ?? items()[0])?.focus();
    });

    pop.addEventListener('click', (e) => {
      const item = e.target.closest(SEL);
      if (!item) return;
      for (const i of pop.querySelectorAll('[role="menuitemradio"]')) i.setAttribute('aria-checked', i === item);
      value.textContent = item.querySelector('.menu-item-text')?.firstChild.textContent.trim() ?? item.textContent.trim();
      btn.removeAttribute('data-empty');
      if (hidden) hidden.value = item.dataset.value ?? value.textContent;
      pop.hidePopover(); // focus goes back to the button
      btn.dispatchEvent(new CustomEvent('select-menu:change', { bubbles: true, detail: { value: item.dataset.value } }));
    });

    pop.addEventListener('keydown', (e) => {
      const list = items(), at = list.indexOf(document.activeElement);
      const to = { ArrowDown: at + 1, ArrowUp: at - 1, Home: 0, End: list.length - 1 }[e.key];
      if (e.key === 'Tab') return pop.hidePopover();
      if (to !== undefined) { e.preventDefault(); list.at(to % list.length)?.focus(); return; }
      if (e.key.length === 1 && !e.ctrlKey && !e.metaKey && e.key !== ' ') { // type to jump
        typed += e.key.toLowerCase(); clearTimeout(clear); clear = setTimeout(() => (typed = ''), 600);
        list.find((i) => i.textContent.trim().toLowerCase().startsWith(typed))?.focus();
      }
    });

    btn.addEventListener('keydown', (e) => { // arrows open it, as a native select does
      if (e.key === 'ArrowDown' || e.key === 'ArrowUp') { e.preventDefault(); btn.click(); }
    });
  }
})();

Accessibility

  • Keyboard. Enter, Space or the Up and Down arrows on the button open the list, with focus on the checked item. Arrow keys move between items and wrap, Home and End jump to the ends, typing a letter jumps to the item that starts with it, Enter or Space chooses and returns focus to the button, Esc closes and returns focus to it, and Tab closes it.
  • Names. The button is named by the label and the current value (aria-labelledby lists both), so a screen reader says "Plan, Standard, button". aria-haspopup="menu" and aria-expanded say it opens a list.
  • The checked item is aria-checked="true", not colour alone: it also has a check mark and a heavier weight.
  • The button and every item are at least 44px tall on touch screens, and the text is at least 16px so phones don't zoom in.
  • In forced colours the check follows the text colour and the focused item takes the system highlight. Opening and closing are instant with reduced motion.
