App shell

The frame a tool app sits in: header, sidebar, main view and a detail panel. It follows its own width, so the same markup is a phone layout, a tablet layout and a three-column desktop.

Wide, 1440px

The sidebar is a column and the selected host's details are a third column. Collapse the sidebar with the button at its foot, and hover or tab through the rail to see each label.

Use it

@import '@brignano/design/tokens.css';
@import '@brignano/design/components.css';
@import '@brignano/design/templates/app-shell.css';

<div class="app-shell" data-sidebar="expanded">
  <div class="app-shell-grid">
    <header class="site-header">
      <div class="site-header-inner">
        <button type="button" class="btn btn-ghost btn-icon app-menu-button"
                popovertarget="app-nav" aria-label="Menu">…</button>
        <a class="site-brand" href="/">…</a>
        <div class="site-actions">…</div>
      </div>
    </header>
    <nav class="app-sidebar" id="app-nav" popover aria-label="Main">
      <button type="button" class="btn btn-ghost btn-icon app-sidebar-close"
              popovertarget="app-nav" popovertargetaction="hide"
              aria-label="Close menu" autofocus>…</button>
      <div class="app-sidebar-section">
        <p class="app-sidebar-title" id="nav-infra">Infrastructure</p>
        <ul aria-labelledby="nav-infra">
          <li><a href="/hosts" aria-current="page"><svg class="icon" aria-hidden="true">…</svg><span class="app-sidebar-label">Hosts</span></a></li>
        </ul>
      </div>
      <button type="button" class="btn btn-ghost btn-icon app-sidebar-toggle"
              aria-controls="app-nav" aria-expanded="true"
              aria-label="Collapse sidebar">…chevron-left…</button>
    </nav>
    <main class="app-main" id="main">…</main>
    <dialog class="dialog app-detail" id="detail" aria-labelledby="detail-title">
      <div class="dialog-header"><h2 class="dialog-title" id="detail-title">pve-01</h2>…close…</div>
      <div class="dialog-body">…</div>
    </dialog>
  </div>
</div>

// your script
const shell = document.querySelector('.app-shell');
const grid = shell.querySelector('.app-shell-grid');
const toggle = shell.querySelector('.app-sidebar-toggle');
const detail = shell.querySelector('.app-detail');

const setSidebar = (state) => {
  shell.dataset.sidebar = state;
  toggle.setAttribute('aria-expanded', String(state === 'expanded'));
  toggle.setAttribute('aria-label', state === 'expanded' ? 'Collapse sidebar' : 'Expand sidebar');
};
try { setSidebar(localStorage.getItem('sidebar') ?? 'expanded'); } catch {}
toggle.addEventListener('click', () => {
  const next = shell.dataset.sidebar === 'collapsed' ? 'expanded' : 'collapsed';
  setSidebar(next);
  try { localStorage.setItem('sidebar', next); } catch {}
});

// selecting an item: a column where there's room, a sheet where there isn't
function openDetail() {
  if (detail.open) detail.close();
  const mode = getComputedStyle(grid).getPropertyValue('--app-detail-mode').trim();
  if (mode === 'column') detail.show(); else detail.showModal();
}

Use when

  • A tool app with several places to go: life, homelab, driftwood.
  • A list or table whose items have details worth a panel of their own.
  • Every place in the sidebar has an icon from icons, because the rail shows only icons.

Don't use when

  • A marketing or content site. Use the site header and footer on their own.
  • An app with one screen. A header is enough.
  • Details that need the whole screen to read or edit. Give them a page of their own.

Layout

  • Under 48rem: one column. The sidebar opens as a sheet from the start, and details as a sheet from the bottom.
  • 48rem to 75rem: the sidebar is a 15rem column, or a 3.5rem rail when collapsed. Details are a sheet from the end.
  • 75rem and up: details become a 22rem third column.
  • These are container queries on .app-shell, so they follow the shell's width, not the screen's.
  • The shell is the viewport's height and only .app-main scrolls. Set a height on .app-shell to put it in a smaller box.
  • Override --app-sidebar, --app-rail or --app-detail-width on .app-shell if a product needs to.

Your script

  • The collapse toggle sets data-sidebar to expanded or collapsed, with its own aria-expanded and label to match. Remembering it is up to you.
  • Open the detail with show() when --app-detail-mode is column, and showModal() when it's sheet. Close an open one first, since showModal() throws on a dialog that's already open.
  • The phone menu needs no script: popovertarget opens and closes it.

The product's mark

  • The glyph beside the name draws in the mark in force: the family amber by default, or the product's own once data-mark="teal", "violet" or "magenta" is set on <html> (or any ancestor). Above, the light wide example is unmarked and the dark one sets teal.
  • Only an inline <svg> in currentColor takes it; an <img> logo keeps its own colours. The name stays ink, and buttons and links stay cobalt on every product.

Accessibility

  • The sidebar is a <nav> with an aria-label, and each list is labelled by its section title. The current page has aria-current="page".
  • In the rail, each label is visually hidden, not removed, so every link keeps its name. It shows beside the icon on hover and keyboard focus. Touch users never hover, so keep the rail for places people already know.
  • The collapse toggle has aria-controls pointing at the nav and an aria-expanded that says whether the labels are showing.
  • On a phone the sidebar is a popover: Esc, a tap outside or the close button closes it, the close button takes focus when it opens, and focus goes back to the menu button when it closes. Like the site header's menu, it doesn't trap focus.
  • A sheet detail is a modal <dialog>: the page behind is inert, Esc closes it, and focus returns to the row that opened it. A column detail is a non-modal dialog beside the list, so the list stays usable.
  • Nav links reach 44px on touch and in the rail.
