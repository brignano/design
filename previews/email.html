Use it

# once, at build time: colours from tokens.css (light theme)
node node_modules/@brignano/design/scripts/email-tokens.mjs \
  node_modules/@brignano/design/templates/email.html > emails/base.html

# per send, fill the content placeholders:
#   subject preheader product heading button_label footer: text, HTML-escaped
#   button_url: an absolute https:// URL
#   body: HTML you build from escaped text, one <p style="margin:0 0 12px;">
#         per paragraph; never a sender's raw input
# and send templates/email.txt (body_text as plain text) as the text part.

When to use it

  • The two emails every lead form sends: the note to the owner and the auto-reply (fleet lead standard).
  • Receipts, sign-in links and other one-to-one messages a product sends.

When not to

  • Newsletters and marketing emails: out of scope.
  • A second button. One action per email; anything else is a plain link in the body.

Rules

  • Colours are token names in double braces, never hex; email-tokens.mjs fills them and fails on a token it can't resolve, and npm run check does the same.
  • Light only: color-scheme: light only, because mail apps rewrite dark colours unpredictably.
  • The product name is text, not an image, so it shows with images blocked.
  • Always send the text part too, from email.txt.

Layout

  • Tables and inline styles, because that is what Gmail and Outlook render.
  • 560px wide at most; under 620px the padding shrinks.
  • System fonts: webfonts don't load in most mail apps.

Accessibility

  • Layout tables carry role="presentation", so screen readers read the content, not the grid.
  • lang and a <title> are set; the heading is a real <h1>.
  • Every colour pair (ink, ink-soft, slate and the link on card or page ground, white on the button) is one of the checked contrast floors.
