Our builds took fourteen minutes. Here's how we got them to six without touching a single test, and what we'd do differently.

Find the real cause

The pipeline rebuilt every package on every commit. A trace showed 80% of the time went to packages nobody had changed.1 See the build dashboard for the raw numbers.

  1. Hash each package's inputs.
  2. Skip the build when the hash is in the cache.
    • The cache lives in the same bucket as the artifacts.
  3. Run tests only for packages that rebuilt.

The cache key

Run npm run build -- --cache locally, or press ⌘ B in the editor.

const key = hash([lockfile, src, process.env.NODE_ENV]);
if (await cache.has(key)) return cache.restore(key);

We cut build times in half without touching a single test.

What it covers

  • Headings h2 to h4 with a .anchor link after the text, paragraphs, links, bold, lists (nested too).
  • Inline code, kbd, pre, blockquote, figure, hr, and footnotes in the shape remark-gfm and markdown-it emit.
  • Tables: wrap them in .table-wrap with .table (a renderer plugin or a component can add the classes).
  • Width stops at the tier's --measure; spacing is --s*.

Don't use when

  • The page is an app screen: forms, dashboards, settings. Use the components directly.
  • You need an h1: the page template owns the title, so prose starts at h2.

Accessibility

  • Give each .anchor an aria-label naming its section; the # is drawn by CSS.
  • Code blocks scroll sideways: give the <pre> tabindex="0" and an aria-label.
  • Links are underlined, never colour alone. Footnote back-links need a label like "Back to reference 1".
